## Project Overview

A centralized database system that integrates crop market price data with farmer crop insurance records. The system automatically detects price distress (when mandi prices fall below MSP) and auto-generates insurance claims when weather conditions (rainfall < 50mm) cross threshold limits using database triggers.

## Database Design

### Tables (11 + 1 audit)
- `FARMER` — registered farmers
- `CROP` — crops with MSP values
- `GOVERNMENT_SCHEME` — PM schemes (PMFBY, PM-KISAN, etc.)
- `WEATHER_EVENT` — rainfall and temperature records
- `MANDI_PRICE` — daily crop prices from mandis
- `INSURANCE_POLICY` — farmer insurance policies
- `CLAIM` — insurance claims (auto-generated by trigger)
- `PAYOUT` — approved claim payouts
- `FARMER_CROP` — M:N junction
- `FARMER_SCHEME` — M:N junction
- `POLICY_CROP` — M:N junction
- `CLAIM_AUDIT` — status change audit log

### Key Features
- **3NF Normalization** — no redundancy, no transitive dependencies
- **3 Views** — Price_Volatility_View, Claim_Detail_View, Farmer_Portfolio_View
- **3 Triggers** — auto-claim on low rainfall, duplicate policy prevention, audit log
- **3 Stored Procedures** — price trend report, bulk claim approval, farmer registration
- **3 Functions** — volatility %, claim eligibility, payout calculation
- **Transaction Management** — COMMIT, ROLLBACK, SAVEPOINT with ACID properties

## How to Run

### Step 1 — Set up the Database
1. Install Oracle Database 21c XE
2. Open Oracle SQL Developer
3. Connect with `SYSTEM` user
4. Open `database/crop_insurance_oracle.sql`
5. Run each section using **F5** in order (Section 0 → Section 12)

### Step 2 — Run the Backend
```bash
cd backend
pip install -r requirements.txt
```
Edit `db_config.py` and set your Oracle password, then:
```bash
python app.py
```
Backend runs at `http://localhost:5000`

### Step 3 — Open the Frontend
Open `frontend/index.html` directly in any browser.  
Make sure the backend (`app.py`) is running first.

## Problem Statement

During 2018–2019, onion prices in Madhya Pradesh and Maharashtra crashed to extremely low levels causing farmer losses. Insurance claim settlements under PMFBY were delayed due to manual verification. This system solves these issues through automated database triggers and integrated price-weather-insurance data.
